# Exclude Sites from Tracking Walkthrough

The "Exclude this site from tracking" button and "Excluded Sites" settings list have been successfully implemented.

## Changes Made

### 1. Types & Models
- Added `excludedSites: string[]` to the persistent `UserSettings` (defined in [types.ts](file:///x:/Projects_X/0_Active/A_XPI_Firefox_Plugin/firefox-plugin-visit-indicator-xpi_GITHUB/visited-page-tracker/shared/types.ts)).
- Initialized `excludedSites: []` by default in `defaultSettings()`.
- Added the `EXCLUDE_SITE` message type (`{ type: 'EXCLUDE_SITE'; host: string }`) to the `ExtensionMessage` protocol.

### 2. Background Script
- In [background.ts](file:///x:/Projects_X/0_Active/A_XPI_Firefox_Plugin/firefox-plugin-visit-indicator-xpi_GITHUB/visited-page-tracker/background/background.ts), updated message listeners:
  - `GET_VISIT_INFO`: If the target URL hostname is in `settings.excludedSites`, returns `record: null` and overrides settings to disable the banner/highlight.
  - `UPDATE_VISIT`: If the URL hostname is in `settings.excludedSites`, ignores the update request.
  - `EXCLUDE_SITE`: Appends the host to the excluded sites array and persists it in user settings.

### 3. Content Scripts (Top Bar Banner)
- In [content.ts](file:///x:/Projects_X/0_Active/A_XPI_Firefox_Plugin/firefox-plugin-visit-indicator-xpi_GITHUB/visited-page-tracker/content/content.ts), added an early check. If the current hostname is excluded, it skips the entire visit logic (no rendering of UI and no call to update visit).

When clicked, it sends an `EXCLUDE_SITE` message to the background with the current hostname, then clears the banner and highlight overlay from the DOM immediately.
